# Audit rules and their fixes

What `harness/zen-figma-audit.js` reports, why it matters, and the fix. Errors block "done"; a warning is fixed or
explained to the user. The audit checks what you authored (frames, text and shapes you made, and what you put in an
instance's slot); a Zen instance's own internals are the library's, so inside an instance it checks only overrides
and text that is crushed or sticks out.

| Rule | Severity | Means | Fix |
| --- | --- | --- | --- |
| `paint/unbound` | error | a solid fill, stroke or text colour with no variable and no style | bind it to a Mode Colors (Semantic) variable by its layer (screen-rules §1): `figma.variables.setBoundVariableForPaint(paint, "color", variable)` and assign the returned paint |
| `paint/gradient-no-style` | warning | a gradient with no style | use a Zen colour style (figma-tokens.md) or a flat token; gradients are rare in Zen |
| `instance/paint-override` | error | a raw colour painted on a layer inside a Zen instance | remove the override: pick the variant that has the colour, or re-create the instance (figma-gotchas.md) |
| `instance/colour-changed` | warning | a layer inside an instance is bound to another variable than the component's own, typically an icon that lost its variant colour after an icon swap | re-create the instance and set the swap from the default (figma-gotchas.md); keep it only if the designer asked for that colour |
| `text/no-style` | error | text with no Zen text style, or a run inside it with none | apply a style from figma-tokens.md (`textStyleId` / `setRangeTextStyleIdAsync`); never set font, size or line height by hand |
| `spacing/unbound` | error | an auto-layout gap or padding with no variable | bind `itemSpacing`, `padding*` and `counterAxisSpacing` with `setBoundVariable` to `Spacing/Gap/*`, `Spacing/Padding/*` or the Breakpoint margins (screen-rules §2) |
| `radius/unbound` | error | a corner radius with no variable | bind all four corners to a `Corner-Radius/*` variable; a box usually takes its component's radius (Card, List-Box) instead |
| `radius/concentric` | warning | a filled layer in the corner of a rounded box does not share its centre: its radius is not the box's radius minus the padding between them (a pill counts as half its short side, so a wide item in a narrow vertical capsule shows an oval in a circle) | make the inner radius = outer − padding; in a vertical capsule make the items square (on the instance only when the library item is shared); user 2026-10-18, iPhone Duo tab strip |
| `effect/no-style` | error | a shadow or blur with no effect style (also an instance whose effects were overridden) | apply a Zen effect style (`effectStyleId`), or remove the effect (no shadow on Subtle, Pale or Surface-Alt fills) |
| `layout/absolute` | warning | a frame with 2+ children and no auto layout | make it an auto-layout frame; keep absolute only for floating overlays on a state frame |
| `layout/row-drift` | warning | side-by-side columns of equal rows (a row header column beside a track, a task column beside Gantt rows) end a row at different heights, so the grid lines drift a pixel per row | give the header cells and the track rows one fixed height; set `strokesIncludedInLayout = false` on every frame that draws a grid rule (`createAutoLayout` counts strokes in the layout) (customize-without-detach.md §5) |
| `shape/loose` | warning | a rectangle, ellipse, vector or line outside any component | use the Zen component it imitates (Divider, Avatar, Dock-Icon, Progress, Skeleton); a custom visual becomes a local component made from variables |
| `component/detached` | warning | a frame named like a Zen component (`Button/Main`…) that is not an instance | replace it with a real instance of that set |
| `bounds/overflow` | error | a layer sticks out of its parent frame (also when the parent does not clip); a Zen bleed is allowed: one button instance centred in a non-clipping icon-size wrapper, spilling evenly on all sides (Sidebar Collapse, AppShell toggle), and a Large Indicator Tab-Bar (64) spilling evenly above and below a header row (its indicator sits on the header's bottom border); so is content that runs on past the far end of a scroll area: its parent, or the nearest clipping ancestor of a parent that does not clip, scrolls that way (the Pattern/AppShell Body or Sheet scrolls vertically) | let the parent hug or fill, shorten the content, or wrap it; never hide it behind a clip, and never turn a bleed wrapper into Hug (it moves the icon) |
| `bounds/clipped` | error | a clipping parent cuts a layer off | as above; give the parent room or turn off the clip only if nothing should be hidden |
| `bounds/stroke-clip-gap` | warning | a clipping frame with an INSIDE stroke and a corner radius has a filled child that reaches a corner: Figma clips the child 1px inside the stroke but keeps the outer radius, so a hairline gap shows at that corner (a colour swatch, a slider fill) | put the fill on the stroked frame itself (one shape), or move the stroke to a top `Border` layer with the same radius (customize-without-detach.md §5) |
| `bounds/shadow-clipped` | error | a drop shadow (also one inside an instance, like a Shadow card's) is cut by a clipping frame of the screen: a frame you made (`createFrame` / `createAutoLayout` clip by default) or slot content; measured from the effects, since `absoluteRenderBounds` is already clipped | turn that frame's Clip content off (`clipsContent = false`), or give the shadow room with padding (by token) |
| `bounds/shadow-clipped-in-component` | warning | the same, but the clipping frame belongs to a Zen component | report it to the designer (a library issue); do not paint or resize inside the instance |
| `text/overflow` | error | text taller than its fixed box, or glyphs past their instance's edge | let the text hug its height (`textAutoResize = "HEIGHT"`), widen the instance, or shorten the copy; truncate (`textTruncation = "ENDING"`) only where Zen truncates |
| `text/crushed` | error | text squeezed into a box narrower than a few characters, or wrapping a word per line | give it a fill width or hug; check the parent's sizing first |
| `text/shifted` | error | left-aligned text with a fixed width sits in a vertical auto layout that centres or end-aligns its children, and the column is wider, so the text starts in from the edge and no longer lines up (a slot's default text, like List-Box's Heading, kept after the box was resized) | set the text to Fill (`layoutSizingHorizontal = "FILL"`, which makes it hug its height); never nudge it with padding |
| `copy/placeholder` | warning | lorem ipsum, or a bare default label ("Title", "Label") in your own text | write the real copy |
| `list-box/footer-text-action` | error | a List-Box footer action ("Open calendar", "Go to Inbox", "View all") written as a text layer in its Footer-Slot | put a Button/Main Tertiary (Medium) there with the label: Fill width on desktop and tablet, Hug on mobile (code: ListBox `footer={<Button>…</Button>}`, harness listbox/footer-action-tertiary) |
| `list-box/footer-action-hug` | error | a Button in a List-Box Footer-Slot set to Hug on a screen wider than 600px (desktop, tablet) | set the Button's width to Fill; it hugs only on a phone screen (code: the footer stretches it, `[data-breakpoint="mobile"]` hugs it) |
| `spacing/section-gap` | error | a screen's section stack (its Body, or the AppShell pattern's Content slot) is not spaced by `Layout-Mobile/Section-Gap` on a phone (Compact 24, Comfortable 32) or `Spacing/Gap/XLarge` (32) on desktop; a pane whose child fills it (a thread over its composer) and Dividers are not sections | bind the stack's gap to that variable (`body.setBoundVariable("itemSpacing", …)`, never a fixed px or a plain ladder step on a phone); then check that each child is a whole section: group content that belongs together (a widget grid, a title row with its list) into one frame first, so the section gap falls only between sections |
| `section/title-apart` | warning | a title row (a heading or kicker, alone or with a See all link) is a child of the section stack with its content as the next sibling: the section gap splits them (a heading over its own paragraph, as a docs step, is a section of text and passes) | put the title row and the content it names in one section frame, `Spacing/Gap/Medium` between them (user 2026-10-21: "không để title riêng, listing riêng") |
| `list-box/closing-list-on-phone` | error | on a phone screen, the last section of the content (a page pattern's Content slot, or the screen) is a List-Box that sits in no row or grid of widgets and is the only List-Box there | make it an open section as `◆ Finance` Transactions: a `Heading` frame (Heading/4 + See All, `Margin-Comfortable` sideways, `Spacing/Padding/Medium` above and below) and a frame of the same `List-Item`s padded `Margin-Comfortable` sideways, gap 0, both FILL; no box (code: `listbox/closing-list-on-phone`, usage rules §19). Grouped lists keep their boxes |
| `theme/box-on-canvas` | error | a box (Card, List-Box, Metric-Card / Chart-Card through their Card) draws a fill that does not belong to the page's Canvas, read from the paint actually drawn | screen-rules §1: Canvas/Default → Surface/Default (Default, Shadow, Border), colour Theme=Subtle (a Pale box there fades into the grey: use Subtle); Canvas/Alt → Pale, Border on Surface/Default, or Surface=Alt; Canvas/Flat → Theme=Flat-Border, or Pale. No gradient box (Semi-Pale, Gradient): one box per row may stand out with Solid (or Subtle on a white page). Set Theme / Surface / Color on the instance |
| `theme/navigation-surface` | error | a header, Sidebar, top or bottom bar does not match the canvas (a bar's own scrim gradient, as a Liquid-Overlay top bar or a Floating bottom bar draws it, is the component's and passes) | no fill, or the Surface of the canvas's colour (Default ↔ Surface/Alt, Alt ↔ Surface/Default, Flat ↔ Surface/Flat); only on Canvas/Default may the Sidebar or bottom bar be a Surface/Default panel |
| `theme/mixed-elevation` | error | a shadow on a Canvas/Alt or Canvas/Flat screen, or on Canvas/Default some surfaces cast one and others do not | remove every shadow (Sidebar `Shadow=No`, the bottom bar's built-in shadow, box Theme without Shadow), or give all of them one (Sidebar `Shadow=Yes`, Theme=Shadow, Shadow/Top/Level-1 on the bottom bar) |
| `theme/mixed-boxes` | warning | one screen mixes box families (Flat, Border, Pale, Subtle) | keep one family; vary the Color inside Pale or Subtle instead |
| `theme/mode-override` | error | a layer inside the screen (a component, a card, a frame) sets its own Light/Dark colour mode | remove the mode (Appearance → back to the inherited one): only the screen frame sets Light or Dark. A dark widget is Card `Theme=Solid, Color=Neutral` with Inverse content; a library component that sets a mode is fixed in the library |
| `theme/on-white-solid` | error | text or a placed icon sits on a `Background/White-Solid` fill (the white Tooltip, a white overlay Button, an On-Color Badge or Dock-Icon, a white panel you drew) with a colour outside `Content/On-White-Overlay/*` | bind it to `Content/On-White-Overlay/Strongest` (title, value), `/Base`, `/Light`, `/Placeholder` or `/Disabled`: White-Solid stays white in Dark mode, so Neutral or Inverse text turns light on it there |
| `theme/on-solid-content` | error | text, a placed icon, a Dock-Icon, Badge, Metric-Tile or Metric-Trend on a Solid fill uses another family than the fill's | screen-rules §1: on `Background/Neutral/Solid` bind text and icons to `Content/Inverse/*` and set Dock-Icon / Badge `Theme=Inverse`, Metric-Tile / Metric-Trend `Content=Inverse`; on `Background/Accent/Solid` use `Content/On-Accent/*` and Metric-Tile `Content=On-Accent`; on Yellow, Sky, Mint, Golden or Warning solids `Content/On-Brights` and Metric-Tile `Content=On-Bright`; on any other Support, Positive, Negative or Info solid `Content/On-Colors` and Metric-Tile `Content=On-Color`. On Accent and colour solids, chips are `Theme=On-Color` and Metric-Trend is `Content=On-Color` |
| `badge/count-uses-counter` | error | a `Badge` instance whose label is a number (unread, items, a section's count) | swap it for `Badge-Counter` with the same Size, Theme and Background: the round pill whose min width equals its height, capped at "99+" (component-usage-rules §18). Keep Badge for words and statuses |
| `navigation/back-chevron` | error | a left arrow (`icon-arrow-left-*`, `icon-arrow-narrow-left-*`) is the Back of a Top-Navigation, Nav-Action or Button on a phone or tablet screen (390–1024 wide, or with `Top-Navigation/Mobile` / `Tablet`) | swap the icon through its instance-swap property (e.g. Leading-Icon-Src) to `icon-chevron-left-line-medium`, the platform back affordance (component-usage-rules §10); the icon keeps its colour variable. Date Picker, Pagination and carousel arrows keep theirs; desktop Side Panel / Modal back arrows are not covered |
| `button/one-primary` | error (side by side) / warning (elsewhere on the screen) | more than one Primary Button/Main or Icon-Main | keep one Primary, the screen's main CTA; set every other action to `Level=Tertiary`. A pair is Tertiary + Primary with Primary last; on a phone footer, Primary on top and at most one Tertiary below (guidelines/button.md) |
| `button/secondary-justified` | warning | a Secondary Button/Main or Icon-Main | Secondary is only a pressed toggle that stays on (a device's power while on, an active mode); anything else is Tertiary. Keep it only with that reason in your report |
| `button/accent-is-promoted` | warning | an Accent Button/Main or Icon-Main | Accent is a promoted CTA (onboarding, upsell, the floating feedback action); a search, cart, lock or save button is Primary |
| `button/small-full-width` | error | a Small, XSmall or 2XSmall text button set to Fill | set `Size=Medium (Base)` (or larger) for a full-width button, or let the small one hug its label |
| `button/overlay-on-imagery` | warning | a Button/Main or Icon-Main sits on a photo | swap to `Button/Overlay` or `Button/Icon-Overlay` (`White` on a light photo, `Black Overlay` / `Inverse` on a dark one); keep the icon through its swap property |
| `button/in-card-flat` | error | a `Button/Icon-Main` showing the ⋮ / ⋯ icon inside a card (any frame or component named …Card, a Card or List-Box instance) | swap it for `Button/Icon-Flat`: Small, Secondary, `icon-dots-vertical-line`, floating in the card's corner (Zen's Card Sub-Action). Only the more menu is flat: other icon actions in a card (power, stepper, playback, call) keep their Icon-Main role, and a ⋮ in a page header stays Icon-Main Tertiary (user 2026-10-18) |
| `button/in-card-wrapper` | warning | the card's flat ⋮ / ⋯ more menu that does not sit in a size wrapper | wrap it in a `Wrapper` frame 20×20, width and height bound to `Element-Size/Popular/Base`, centred, Clip content off (the Card Sub-Action): the 32px button bleeds evenly and the row keeps the icon's size |
| `spacing/control-gap` | error | a button sits closer than 8px to the heading, label or button beside it (an auto-layout gap below Gap/XSmall) | bind the gap to `Spacing/Gap/XSmall` (a thing and its control, controls in one toolbar row) or more; `Gap/2XSmall` joins only one inline item: an icon and its text, a Badge beside a title. A bleed wrapper (Card Sub-Action) is not a button and is not checked |
| `button/vague-label` | warning | a button labelled OK, Yes, Submit or Click here | name the outcome with a verb ("Save changes", "Select", "Send invite") |
| `touch/target-spacing` | error | on a phone or tablet screen, two controls (buttons, Chips, Toggles, fields, Segmented, Tabs, Search) sit closer than their 44px hit areas allow | raise the gap of their parent to the ladder step at or above what both lack of 44 (two 32px rows → `Spacing/Gap/Small` 12; a 32 and a 40 → 8; a 24 Toggle and a 32 → 16). Never shrink a control to make it fit |
| `spacing/controls-to-content` | warning | a control row (Chips, Segmented, Tabs, Search) sits closer than 16 to the content it controls | set that gap to `Spacing/Gap/Medium` (16), or wrap heading + controls in their own frame and give the section gap Medium; a control row is a block, not a label |
| `search/toolbar-width` | error | on a tablet or desktop screen, a Search wider than 240 sits in a toolbar row beside Chips, buttons or other controls (the user's rule 2026-10-24) | set the Search (or the wrapper that holds only it) to Fixed 240, or Fill with a max width of 240 (screen-rules §4 Toolbar Search); a phone Search (Shape=Rounded) fills its row, and a top bar's or the Dashboard header Control-Bar's own Search is sized by its component |
| `list-item/leading-dock-icon` | warning | a List-Item leads with a bare icon instance (the user 2026-10-24: "các list item hạn chế dùng icon không. Thường nên dùng dock icon") | swap the leading instance for a `Dock-Icon` (Size Medium, Background Subtle) holding that icon, or an Avatar / a thumbnail |
| `badge/status-priority-icon` | warning | a priority Badge (Urgent, High, Medium, Low) whose Leading-Icon is off or is not `icon-flag-03-solid`, or a status Badge (Paid, Active, Overdue…) with Leading-Icon off; a Badge in a Table cell counts | turn Leading-Icon on; for a priority swap Leading-Icon-Src to `icon-flag-03-solid` (`.Task/Priority`); a workflow step is a `Badge-Status` |
| `app-shell/top-row-filled` | warning | a Header/AppShell on a tablet or desktop screen shows its top row (Top-Header on) with nothing in Top-Elements | fill it: Breadcrumbs or a Search on the left, a Search in the centre (up to 400) when it helps, and help, notifications (`Header/Action-Item` with its count) and the account Avatar last on the right; or turn Top-Header off for a Main-only header |
| `priority/palette` | warning | a priority Badge outside the one palette (the user 2026-10-24: "badge ưu tiên trung bình nên đồng bộ dùng yellow thay vì orange") | set Theme: Urgent and High `Red`, Medium `Yellow`, Low `Neutral`, each led by `icon-flag-03-solid`; Property-Field priority icons take tone Negative / Warning / Neutral |
| `navigation/icon-style` | error | a Bottom-Navigation item whose icon style does not match its selection (a solid icon on an unselected tab, a line icon on the selected one) | set each item's `Icon-Src` from its line/solid pair: the selected item `icon-…-solid`, the others `icon-…-line` of the same family. An icon without a solid version (magic-wand) is not a tab icon: pick one that has both (Scenes → `stars-01`). When the selection moves, swap both items |
| `navigation/floating-fit` | error | a `Bottom-Navigation/Mobile/Floating` or `Floating-Glass` (phone or tablet) whose tabs leave 64–88: the capsule fills while its tabs would pass 88, hugs while they need 88 or less, or holds more tabs than fit at 64 | Fill while the tabs share the room at 88 or less (a phone: 4–5 tabs, 3–4 beside the action); past 88 (2–3 tabs on a phone, any tablet, the Duo) set `Container` and its `Nav-Item` slot to Hug and every tab Fixed 88, the `Items` row Center, or Space between with the action. More than fit at 64 (6 on a phone, 5 beside the action) go in More or use `Bottom-Navigation/Mobile/Default` |
| `navigation/status-in-bar` | error | a status bar placed above a `Top-Navigation/Mobile` whose own `Status-bar` is hidden: it sits on a band of its own and the bar's gradient or colour starts under it (an iPad screen built from the phone bar) | swap the Top-Navigation's `Status-bar/IOS/Mobile` to the device's (`Status-bar/IOS/Tablet` on an iPad), show it (Fill width) and remove the separate one; an overlay bar keeps its status in Dark as the phone's does |
| `empty-state/size-by-container` | error · warning | an Empty-State whose Size does not fit where it sits: Medium inside a Card, table, list, pane, panel, sheet, popover or dialog (error); Medium beside other blocks of the page, or Small alone on an empty page (warning) | Size=Medium (240 illustration) when the Empty State fills the page's main content (first run, no results, no access); Size=Small (200) when it fills one region of a page that still shows other content — the code EmptyState `size` rule |
| `navigation/collapse-beside-master-crumb` | error | a Header/AppShell with its sidebar toggle (Collapse Button) on whose breadcrumb starts with a Level=Master item: the toggle and the home icon read as two icons in a row | start the trail with a Level=Sub item, or keep the Master item and move the toggle to the sidebar's header (Pattern/AppShell/Desktop Collapse=Sidebar: the header's toggle off, the sidebar's on) |
| `modal/dialog-form` | error | a Modal/Dialog holds two or more Input fields | a Dialog is a notice or a quick confirm: put the form in `Modal/Forms` (desktop, tablet) or a `Bottom Sheet` (phone) |
| `modal/form-actions-vertical` | error | a Modal/Forms whose Actions are `Direction=Vertical` | set the nested `.Primitives/Modal/Actions` to `Direction=Horizontal`: a form keeps its actions in a row |
| `modal/form-on-phone` | error | a Modal/Forms on a phone screen (narrower than 744, or with a Top-Navigation/Mobile) | open the form in a `Bottom Sheet`: its title, the fields, the actions in its footer |
| `modal/form-side-taller` | warning | a Modal/Forms whose Side-Content is taller than the form, so the actions float above an empty band | shorten the side (a summary, an illustration) or move its content into the form; Figma cannot stretch the form column to the side's height |

Content that runs on past the far end of a frame set to scroll (a screen with Prototype → Overflow Vertical, a Chip
row with Horizontal) is scroll content and is not reported as `bounds/clipped`. Set the screen to scroll and its bars
to Fixed instead of trimming content that no longer fits after a mode change.

Run it again after every fix batch. It shows at most `MAX_PER_RULE` (25) findings per rule; `counts` has the totals.
