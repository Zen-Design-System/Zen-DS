## 3. Hierarchy

The Toolbar title is the period ("September 2026"), an `h2` in Heading/3 (prop `titleLevel`, default 2) under the
page's h1, with `aria-live="polite"` so Previous / Next / Today announce the new period. Agenda day kickers and the
desktop date column are not headings (meta). No other headings inside the views.

## 4. Interaction (APG)

- Toolbar: Today, Previous, Next are buttons (labels `today`, `previousPeriod`, `nextPeriod`); the view switch is
  Segmented (its own radiogroup keys). Main action (New event) stays in the page header.
- Month desktop: `role="table"` (rows, weekday column headers, cells). Each cell's date is a button named with the full
  date and its event count; it selects the day (`aria-pressed`), today carries `aria-current="date"`. Arrow keys move
  between date buttons (± 1 day / ± 1 week), Home / End to the week's ends. Event chips are buttons when the app handles
  them (`onEventClick`), else static. "+N more" is a button (`onMoreClick`).
- Month mobile and Week-Strip Dot: DatePickerItem buttons (full-date names, `aria-current` today), selected day
  `aria-pressed`; arrows move between days like the month grid.
- Time-Grid: event blocks are buttons with `onEventClick` (name: title, time); pressing an empty slot calls
  `onSlotPress(start)` (pointer only; keyboard users create from the page action). Hours, slots and the now line are
  decorative.
- Agenda: rows are static unless `onEventClick` (then a button per row).
- Selected (event / block) = "while its popover is open": the app sets `selected` with its Popover open state.

## 5. States

Default, hover (Flat tint on pressable events / blocks / rows: never Subtle/Surface for a fill-less item), pressed,
focus-visible (3px Focus/Accent ring), selected (Figma State=Selected), today, muted / outside, empty (Agenda →
EmptyState; Month/Time-Grid show the empty grid). Disabled and error: n.a. (a calendar view has no disabled state).
Loading: n.a. in the component (apps show Skeleton).

## 6. Responsive and modes

`device` follows the nearest `data-breakpoint` (else ZenProvider), as DatePicker does; Time-Grid `view` defaults to
`week` (desktop) / `3-day` (mobile). Comfortable density grows paddings through tokens; the 64px hour and the 24 / 36
dates stay (Figma sizes). Radius modes act through the tokens; dark through the colour tokens.

## 7. API (React)

```ts
type CalendarColor = "brand" | "blue" | "violet" | "teal" | "green" | "orange" | "pink";
interface CalendarEventData { id: string; title: string; start: Date; end?: Date; allDay?: boolean; color?: CalendarColor;
  meta?: string; attendees?: AvatarStackProps["items"] }
```

Views take `events`, `today` (default device clock) and `device`; Month and Week-Strip take the selected day as
`value` / `defaultValue` / `onValueChange` and the shown period as `month` / `week`; Time-Grid takes `date`, `view`,
`startHour` (8), `endHour` (18), `now`. Labels in `_shared/labels.ts` (en + vi).
