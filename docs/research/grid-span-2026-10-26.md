# Grid cell span: `span` / `rowSpan` in code, Zen Studio and Figma

Status: **approved by the user on 2026-10-26 with D1–D6 as recommended** ("Duyệt kế hoạch span với D1–D6 như đề xuất.
Bắt đầu PR A (library), rồi PR B và plugin"). Built: PR A (library, #321, merged as 2e7627e8); the plugin's import sets
the spans (0f966b5 on `studio-import`); PR B (Studio Inspector, push, native paste, pull, docs) on
`zen/feat/grid-span-studio-20261026`. Two changes while building: `DashboardTemplate` keeps its auto-fit rows (§10), and
the canvas column guides of D4 are not drawn yet: a selected Grid's gap areas (SpacingLayer) mark its gutters, and
whether that is enough is checked in the Studio before more is built.

Why: the dashboard layout principles (`skills/zen-component-usage/references/dashboard-layout.md`) lay a dashboard out in
12 parts, with a hero at 8 beside a companion at 4 inside one grid. Zen's Grid cannot say "this cell takes 8 columns", so
today each row is its own Grid: rows written as `"2fr 1fr"` end about a third of a gap (~5px) away from a 3-column row,
tablet reflows that need "this one goes full width" can't be written, and Figma frames built with mixed spans lose them
on the way into Studio.

## 1. Today (code read 2026-10-26)

| Area | What it does now |
| --- | --- |
| `Grid` (`src/components/Layout/Layout.tsx`) | `columns` (a count, a track list, per breakpoint, resolved in JS at the frame's breakpoint), `minColumnWidth` auto-fill, `stackBelow` (one column by the Grid's own width, measured). Children are placed one per cell; nothing reads a child's span. |
| Child sizing (`Layout/sizing.ts`) | `width`, `height`, min/max, `alignSelf` as `data-*` + custom properties. Taken by Stack, Grid, Box, Text, Shape, Card, ListBox. ChartCard and MetricCard render a Card but don't pass sizing through. |
| Studio inspector | Per-breakpoint fields for Stack/Grid/Box (`tools/studio/responsive-props.mjs` `RESPONSIVE_PROPS`, `LayoutSection.tsx`); an instance without size props gets a Studio wrap Stack for W / H (`InstanceSizeGroup.tsx`). |
| Push (`tools/studio/figma-push.mjs`) | A Grid with a column count becomes a Figma Grid auto layout (Flex tracks); every child gets `cell = { row, col, span: 1 }` by index, and cell widths by index. |
| Native paste (`figma-native.mjs`) | Writes the cell's row/column anchors and `gridColumnSpan` when `span > 1`; no row span. |
| Plugin import (`zen-ds-figma-plugin`, `src/plugin/studio-import.js`) | Sets the child's position (`setGridChildPosition`); no span. |
| Pull (`figma-pull.mjs`) | Reads each child's anchors and `gridColumnSpan` / `gridRowSpan`; turns spans into a Grid only when every cell shares one span (8 columns, 2 each → 4 columns). Mixed spans are lost. |

## 2. The API

```tsx
<Grid columns={12} gap="md">
  <MetricCard span={{ desktop: 3, tablet: 6 }} … />            {/* ×4 */}
  <ChartCard span={{ desktop: 8, tablet: "full" }} … />
  <ListBox span={{ desktop: 4, tablet: 6 }} rowSpan={2} … />
  <ChartCard span={{ desktop: 8, tablet: 6 }} … />
</Grid>
```

- **`span`**: how many of the parent Grid's columns the child takes: a whole number or `"full"` (the whole row), per
  breakpoint like the other layout props (`{ desktop, tablet, mobile }`, a missing breakpoint takes the next wider
  one's). Unset = 1.
- **`rowSpan`**: how many rows it takes (a whole number, per breakpoint). Unset = 1.
- **Clamped to the Grid:** the Grid shares its resolved column count with its children (a React context), so a span
  never exceeds it; while the Grid is stacked (`stackBelow`, or one column) every span becomes the full row and row spans
  are dropped. In an auto-fill Grid (no `columns`) only `"full"` applies; a number is ignored (the column count there is
  not known in advance).
- **Placement stays in reading order** (CSS auto-placement, not `dense`): a span that doesn't fit the rest of a row
  starts the next row and leaves a hole, which the dashboard principles' "rows add up to 12" avoids. Order is never
  shuffled for the eye, so keyboard, screen reader and phone order stay the layers' order.
- **CSS:** `data-span` / `data-row-span` and `--zen-cell-span` / `--zen-cell-row-span` → `grid-column: span …` /
  `grid-row: span …`, `"full"` → `grid-column: 1 / -1`, scoped to a Grid's direct children (a mode scope adds no DOM
  element, so the child selector holds).
- **Who takes it** (decision D1): the layout primitives (Stack, Grid, Box) and the boxes that sit in widget grids (Card,
  ListBox, ChartCard, MetricCard). Anything else goes in a `<Box span>`; Studio does that wrap by itself, as it already
  does for W / H.

## 5. Figma (PR B + the plugin)

1. **Push:** a small auto-placement routine (CSS row-major, sparse, with row spans) gives each child its row, column and
   spans, and the Grid's row count; cell widths add up the spanned tracks and gaps (for the children's own layout). The
   page is pushed at its Screen's breakpoint, so the spans are that breakpoint's.
2. **Native paste:** writes `gridRowSpan` beside `gridColumnSpan` (the kiwi schema Figma ships carries both).
3. **Plugin import** (repo `zen-ds-figma-plugin`, `studio-import.js`): after `setGridChildPosition`, set
   `gridColumnSpan` / `gridRowSpan`; the row count is set before the children. `npm test` there, then the real-Figma
   test bed (the Dashboard export in "Studio exports — QA").
4. **Pull:** a Grid auto layout with mixed spans becomes `<Grid columns={n}>` with `span` / `rowSpan` on its children
   (a Box wrap for an instance whose component has no `span`). Cells placed out of reading order (Figma lets a child sit
   anywhere) come in order, with a note.
5. **Update from Figma** (`figma-diff.mjs`): a changed span writes only that breakpoint's key, as the other responsive
   props do.
6. Selftests: figma-push (placement with holes, row spans, widths), figma-native (both spans), figma-pull (mixed spans,
   the Box wrap), figma-diff, native-diff.

## 7. Decisions for the user

- **D1 Where span lives.** *Recommended:* a prop on the child (Stack, Grid, Box, Card, ListBox, ChartCard, MetricCard;
  anything else in a `<Box span>`), as Figma puts span on the child. Other options: a `GridItem` wrapper around every
  cell (one more layer in Studio and Figma), or a `spans` list on the Grid by child index (breaks when cells are
  reordered).
- **D2 Values.** *Recommended:* whole numbers and `"full"`, per breakpoint, clamped to the Grid's columns; only `"full"`
  in an auto-fill Grid.
- **D3 Row span now.** *Recommended:* yes, in the same PRs (the companion column beside a hero, Figma has it).
- **D4 Studio canvas.** *Recommended:* the inspector fields and the column guides now; dragging a cell's edge to change
  its span in a later PR.
- **D5 A harness rule** (e.g. a warning for a row that leaves columns empty, or a number span in an auto-fill Grid).
  *Recommended:* no rule (the layout guidance stays principles); the inspector only shows how many columns a row leaves
  empty.
- **D6 Existing screens.** *Recommended:* rebuild `DashboardTemplate` and the Layout example with spans in PR A; the
  Studio page `quan-ly-task` only if you ask (it is your page).

## 9. Risks

- A span larger than the columns makes CSS add columns: the clamp needs the Grid context, so a span outside a Grid (or
  in a plain CSS grid) does nothing.
- Figma's Grid auto layout needs its row count before a child is placed in a later row; a Fill child across spanned
  tracks must stay Fill (checked in the real file).
- Holes are possible by design (no `dense`); the principles and the inspector hint keep rows full.
- Several sessions touch `figma-push.mjs` / `figma-pull.mjs` most days: PR B claims those files with Giám sát first.

## 10. Found while building PR A

- **Spans follow the breakpoint, not the Grid's own width.** A breakpoint is the window's (or a frame's `modes`), so a
  12-column Grid in a narrow desktop window (1024 wide with the Sidebar open: about 736 of content) still gives a KPI
  over 3 columns about 170px. `DashboardTemplate` reflows by its own width today (auto-fit rows: four KPIs, two by two,
  or stacked), which handles that range better than per-breakpoint spans. So PR A leaves the template as it is (its rows
  already share one gap, so they read as one grid) and shows spans in the Layout page's "One dashboard grid" example;
  Studio Screens and Figma frames have the exact width of their breakpoint, where spans fit as planned.
- A follow-up to decide: let a Grid resolve `columns` and its children's spans at its own width class (for example a
  Grid measured below 744 lays out as tablet), as `stackBelow` already measures it. Then the template can move to spans.
